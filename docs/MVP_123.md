a feature wishlist and it does not replace implementation work. A row is
`done` only when the repository contains the implementation and proportionate
offline evidence. `partial` means useful implementation exists but the stated
guarantee is not closed. `pending` means the product work is not implemented.

Telegram or launchd; a mocked test cannot close it.

## Counting rules

- Only `done` contributes to the completed count.
- A unit or integration test can close an offline guarantee, but it cannot close
  a row explicitly requiring real hardware, Keychain, Telegram, a model,
  launchd, login/reboot or sleep/wake.
- Partial work stays `partial` until the missing guarantee in the final column
  is proved.
- Every implementation wave updates this file in the same change that adds its
  evidence; counts are derived from rows, never edited independently.
